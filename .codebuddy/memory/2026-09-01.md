## 项目方向确认：国内 GEO 自用品（开源二开路线）
- 用户目标：做**国内市场的 GEO（生成式引擎优化）产品**，自用、不商用。
- 明确需求：**自动生成内容 + 自动发布到多平台**（仿蚁小二的分发能力，但蚁小二本身是"多平台一键分发工具"，非 GEO，且 40+ 平台发布能力靠逆向接口/养号，不适合自研）。
- 决策路线：**找成熟开源项目二开**，而非从零写或逆向。

### 已调研到的对口开源项目（重点）
1. **Goodie AI-GEO 洞察平台**（GEO 监控端）
   - 仓库：https://github.com/lorin-code/ai-geo-monitoring
   - 技术栈：Next.js + React + Ant Design / Express + Sequelize / SQLite
   - 已支持国内 5 平台：豆包、DeepSeek、Kimi、通义千问、腾讯元宝
   - 功能：品牌检测任务、多平台检测、提及识别、关键词命中、回答归档、历史记录、定时检测、后台管理；可本地部署二开
2. **MediaPublishPlatform / MPP**（自动发布端）
   - 仓库：https://github.com/funfan0517/MediaPublishPlatform
   - 协议：MIT（可自由改，自用合规）
   - 技术栈：Python + Flask + Playwright + SQLite / Vue3 + Element Plus
   - 已支持 9 平台：小红书、抖音、快手、B站、百家号、腾讯视频号、TikTok、Instagram、Facebook
   - 功能：一键批量发布、定时发布、多账号 Cookie 管理、发布记录、RESTful API；新增平台只改 platform_configs.py

### 拼合方案
Goodie(监控) + MPP(发布) + 自加 AI 生成模块(接 DeepSeek/豆包) + 统一品牌/账号后台 = 用户自己的 GEO 自动生成发布闭环平台。

## GEO 可见性闭环看板(F17,已交付,8/8 验收通过)
- 新增/改动文件(均 `apps/geo-core/`):`visibility_loop.py`(闭环归因:基线→触发检测→对比→落库)、`db.py`(新增 `visibility_snapshots` 表 + 读写函数)、`dashboard_api.py`(升级为闭环看板:聚合生成/发布+监控端 trend + 归因快照,7000 端口,原生 SVG 折线图,真实数据)、`acceptance_loop_test.py`(端到端 8/8)。
- **闭环真实链路**:`MonitorClient.create_project`(同名幂等复用,避免 409) → `ContentGenerator` 生成 → `PublisherClient` 发布(无Cookie明确报错落库) → `visibility_loop.run_visibility_loop` 取 before(监控端 dashboard.summary)→ `detect`(带 project_id)→ 轮询 status 至 completed → 取 after → 计算 Δ → 落 `visibility_snapshots`。
- **实测验收结果(真实检测前后)**: mention_rate 66.67%→68.75%(+2.08%), 合成可见性指数 53.34→55.0。快照 Δ 如实展示(含负值也存,不粉饰)。
- **关键契约修正(避免再踩,重要)**:
  1. 监控端 `/detection/create` 返回 `data.results:[{record_id, platform, status}]`(**数组**,字段名 `record_id` 非 `id`)—— 整合层 `detect()` 此前取 `det.get('id')` 导致 record_id=None,已改为返回 `{record_id, platform, status}`。
  2. 监控端 `summary.brand_mention_rate` 是**百分比(如 57.14)非 0~1 比例**—— 合成可见性指数公式必须 `/100`,否则爆成 4571。公式:`mention_rate(%) /100*50 + avg_share_of_voice(%) /100*30 + citation_rate(%) /100*20`(0~100)。监控端原生无单一整体 visibility_score,故合成,全真实字段。
  3. 监控端 `summary` 无 `avg_visibility_score` 字段(visibility_score 仅存于竞品维度)—— 故整合层自己合成指数。
- **登录 429 限流处理**: 监控端 `user.js` 原 `windowMs=15min/max=5` 对本地自动化验收过严。已放宽到 `windowMs=60s/max=20`(注释说明自用二开环境放宽,可改回)。同时 `MonitorClient` 增加 token 缓存(`token_cache.json`,24h,JWT 实测 24h 有效),正常业务复用 token 不再触发登录限流。`token_cache.json`、`.env` 已加入 `apps/geo-core/.gitignore`(不入库)。
